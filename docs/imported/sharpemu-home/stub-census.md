# Stub census: the one-line success shells in `src/SharpEmu.Libs`

Generated by `python3 scripts/stub_census.py`. Regenerate after any change to
`src/SharpEmu.Libs`; the numbers below are measurements, not estimates.

A **success shell** is an export whose entire body reduces to `return <constant >= 0>`.
It tells the guest "done" and does nothing. That is fine when the real firmware
function also does nothing, and it is a **lie** when the real one writes an
out-parameter, mutates state, or computes a value -- the guest then proceeds on a
false premise and the failure surfaces thousands of calls later as a black screen.

## Headline findings

1. **1056 of the 4255 registered exports in `src/SharpEmu.Libs` are success shells** --
   25%. `grep -c '=> Ok(ctx);'` finds 296 of them; the other 760 are the same thing
   spelled differently.
2. **814 of those are lies**: the real 4.03 function does real work and we do none of it.
3. **0 return success where the real function returns a specific error code.** That is
   the sharpest form of the problem in the whole census: the guest asks whether a
   feature is available, the console says *no* with a documented errno, and we say
   *yes* and then do nothing. `sceKernelHasNeoMode` is the clearest one -- 4.03 returns
   `1`, we return `0`. See [TRIVIAL](#trivial-firmware-returns-a-constant).
4. **Only 37 are honest**, i.e. the firmware body provably does nothing either. Those
   now carry a `[VerifiedFirmwareNoOp]` attribute in the source with the module,
   vaddr, `st_size`, bytes and disassembly that justify them, so a runtime census can
   exclude them instead of re-flagging them forever.
5. **203 are phantoms** -- no 4.03 module exports the NID at all.
6. **Astro Bot imports 3 of the 1056 shells**, and none of them is a LIE. Whatever is
   black-screening Astro Bot, it is not this list.

A counter-example worth keeping in view: `sceAgcDriverRegisterResource` is a 6-byte
firmware body, `mov eax, 0x8a6c9018 / ret`, and
`src/SharpEmu.Libs/Agc/AgcExports.cs:3609` returns exactly `0x8A6C9018`. It never
appears below, because returning the constant the console returns -- error or not --
is the correct implementation and not a stub at all.

## How the list was derived (not a grep)

1. `scripts/our_nids.py` supplies the exact registered-export set: it reimplements
   `SysAbiExportGenerator`'s admission rules (shape, accessibility, NID derivation,
   `Target` filtering, `#if` regions, first-registration-wins) and is verified
   byte-for-byte against the compiler-emitted `SysAbiExportRegistry.g.cs`.
2. Each export body is reduced by `ShellAnalyzer`: expression bodies, single-`return`
   blocks and `{ ctx[Rax] = K; return K; }` blocks are followed through
   argument-free / constant-argument calls into other static helpers until a
   compile-time constant falls out. Anything that reads an argument register,
   touches memory, branches, or calls something unresolvable fails the reduction.
3. The NID is looked up in `scripts/fw_export_bodies.tsv` (mined by
   `scripts/fw_export_bodies.py` from the 589 cleartext 4.03 modules; carries
   `st_value` and `st_size`) and the real body is decoded with capstone.

```
registered exports in src/SharpEmu.Libs : 4255
  SUCCESS SHELLS (constant >= 0)        : 1056
  constant-ERROR shells (return < 0)    : 0   (honest: they say 'no')
  not a single-return shell             : 3199
```

## LIE list, sorted by firmware body size

Bigger body = more work being skipped. Every clause of the last column is counted
off the decoded instruction stream, never guessed:

- `writes *argN` -- an instruction whose destination is memory based on the Nth SysV
  argument register, counted only while that register still holds the argument (any
  write to it, and any `call`, closes the window). A **lower bound**: a function that
  stashes `rdi` in `rbx` and writes through `rbx` is not credited here.
- `writes N module globals` -- rip-relative stores, i.e. the library's own state.
- `N stores through a pointer` -- stores whose address comes from a register other
  than `rsp`/`rbp`/`rip`, so not this function's own stack spills. This is memory
  the caller can observe.
- `reads argN`, `N calls`, `N branches`, `N insns` -- direct counts.

A row with `writes *arg1` is the clearest case: the guest passed an out-pointer, the
real function fills it in, and we leave whatever was in it and say OK.

`scripts/stub_census.py` also writes `scripts/verified_noops.txt` in the exact
format `SharpEmu.HLE.Diagnostics.HleVerifiedNoOps` already reads
(`nid | name | evidence`, one per line, evidence mandatory):

```sh
SHARPEMU_HLE_VERIFIED_NOOPS=scripts/verified_noops.txt <boot the emulator>
```

That is the whole handshake between the static census and the runtime one: with it
set, the runtime effect census stops re-flagging the 37 exports that are *supposed*
to do nothing, and everything left in its "returned success and changed nothing"
ranking is a genuine finding.

of `libSceLibcInternal.sprx`, and this census reaches `0xd4db0 / 1 / c3` through
`scripts/fw_export_bodies.py`.

## What this census does NOT prove

- **It is an index, not the runtime census.** It answers "whose body is a constant
  success return?". It cannot answer "which export was called 40000 times and did
  nothing?". Only a real boot can, and that is the measurement that matters.
- **It misses the bigger class.** 3199 exports in this assembly are *not* single-return
  shells, and an unknown number of them read their arguments, validate them, and
  still change nothing observable. A static scan cannot separate those from the ones
  that do real work; `scripts/our_nids.py` already flags the shape but not the
  outcome. Those are invisible here and are the most likely home of a black screen.
- **`pick_primary` picks one definition per NID.** A NID is a hash of the name only,
  so several modules can export it; the census prefers the module whose export
  library matches the one our attribute claims, and falls back to the largest body.
  Where our attribute names a library the firmware does not use for that symbol
  (`libc` vs `libSceLibcInternal`, `libScePosix` vs `libkernel`), the fallback is
  what chose the row.
- **The firmware body classifier is conservative in one direction only.** Anything it
  cannot prove inert is called work, so the LIE bucket may contain a few functions
  that are effectively inert; it will not contain the reverse mistake.
- **`st_size == 0`.** 242646 of the 297359 exported firmware symbols carry no size,
  but they are almost entirely inside managed `*.dll.sprx` assemblies. Every native
  module we care about (`libkernel`, `libSceLibcInternal`, `libSceNKWebKit`, ...)
  emits real sizes, and no row in this census landed in the UNKNOWN bucket.
